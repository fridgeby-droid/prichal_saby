# Самовывоз 0.5.0 — геолокация и минимум заказа

## Обновление на Bothost

1. Сохраните резервную копию PostgreSQL и текущего проекта. Замените файлы приложения содержимым архива. Dockerfile должен остаться в корне проекта.
2. Сохраните существующие переменные окружения, DATABASE_URL и постоянный каталог /app/data с фотографиями. Архив не содержит базы, фотографий или секретных ключей.
3. Добавьте переменные:

```dotenv
PICKUP_GEO_REQUIRED=true
PICKUP_MINIMUM_RUB=1200
PICKUP_MINIMUM_BY_STORE={}
```

Минимум задаётся в рублях. Для отдельного магазина, например:

```dotenv
PICKUP_MINIMUM_BY_STORE={"23109":1500}
```

4. Пересоберите и перезапустите приложение, затем полностью закройте и откройте Mini App. Структура существующей таблицы pickup_cache подходит для хранения профилей; ручная миграция не требуется.
5. Для оформления нужен существующий режим integration и авторизация Telegram. В режиме catalog доступен просмотр. Для локального demo без Saby задайте PICKUP_GEO_REQUIRED=false.

## Как это работает

Покупатель соглашается сохранить местоположение и нажимает «Определить местоположение». Требуются HTTPS, разрешение на геолокацию и поддержка геолокации браузером Telegram. Сервис адресных подсказок и ключи карт не нужны. Получаем координаты устройства, а не введённый адрес; выбрать другой адрес пока нельзя.

Сервер проверяет точку по районам district/list каждой настроенной точки Saby. Проверяется не только центр координат, но и круг заявленной погрешности: точность должна быть не хуже 100 м и круг должен целиком лежать внутри района. При отказе в разрешении, недостаточной точности, отсутствии подходящего района или ошибке проверки оформить новый заказ нельзя. Если районов больше одной страницы, проверка блокируется до добавления пагинации.

Точка сохраняется в PostgreSQL под ID авторизованного пользователя Telegram. При следующих посещениях проверяется сохранённая точка; новое определение автоматически не запускается. Это не подтверждение текущего физического присутствия человека. При смене места покупатель должен определить точку заново. Старую точку удаляем перед новой попыткой, даже если новая попытка неудачна.

«Удалить сохранённую точку» удаляет её из профиля. Снимок точки уже созданного заказа сохраняется вместе с заказом. Вручную введённый адрес не используется для проверки района.

Доступны только магазины, чей район покрывает точку. При нескольких совпадениях покупатель выбирает магазин. Нет автоматического выбора по кратчайшему расстоянию. Пока известен только тестовый район РЦ: районы остальных магазинов нужно настроить в Saby; район РЦ им автоматически не копируется.

Минимум проверяется и в корзине, и на сервере при создании заказа и первого платежа. Проверка района также повторяется при создании заказа и первого платежа. Уже созданный платёж не пересоздаём. Старые неоплаченные заказы без сохранённой точки не смогут создать новый платёж при включённой геопроверке — оформите новый заказ.

## Все магазины и общий прайс

При готовности районов и прайса можно задать существующую переменную:

```dotenv
SABY_STORE_PRICES={"37462":40,"5635":40,"5604":40,"5617":40,"5629":40,"33446":40,"5611":40,"5590":40,"5583":40,"23109":40,"5623":40,"398":40,"5598":40}
```

Прайс 40 общий, остатки запрашиваются отдельно для каждой точки существующим механизмом каталога. Сборка не меняет ваши текущие настройки автоматически. Проверьте доступность прайса для каждой точки перед подключением всех магазинов.

## Проверка

Диагностика районов (команда только читает данные):

```sh
python manage.py saby-districts 23109
```

В Telegram проверьте: точка внутри тестового района, сумма 1199 ₽ и 1200 ₽, повторное открытие приложения, удаление точки, точка вне района и отказ в разрешении. Платежи продолжайте проверять тестовым ключом ЮKassa.

## Ограничения этой сборки

Расписание и TEST_AUTO_PICKUP_TIME оставлены как в предыдущей версии. Эта сборка не завершает работу с графиком 19:00–02:00 и не является подтверждением готовности к реальным платежам. Модификаторы тары не добавлены.

Проверено локально: 60 автоматических тестов, синтаксис JavaScript. Тесты новых правил покрывают границы и отверстия полигонов, погрешность, минимум, разделение профилей, повторную проверку перед оплатой и отказ Saby. Запросы к живому Saby, PostgreSQL Bothost и интерфейс на телефоне требуют проверки после обновления. Локальные тесты выполнены на FastAPI 0.142.2, Pydantic 2.13.5; зависимости Docker остаются закреплёнными в requirements.txt.
