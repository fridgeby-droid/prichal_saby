# Самовывоз 0.4.0 — всё на Bothost

Приложение и Telegram Mini App работают на Bothost. Каталог, цены, остатки,
описания и заказы хранятся в PostgreSQL Bothost. Фотографии скачиваются из
Saby в постоянную папку `/app/data/photos`. Timeweb и S3 не нужны.

## 1. Создайте отдельную базу PostgreSQL

В панели Bothost создайте PostgreSQL для Самовывоза. Не используйте базу CORE
или AI: у этого приложения собственные таблицы. Скопируйте строку подключения
в переменную окружения приложения `DATABASE_URL`. Сохраните параметры TLS,
которые выдаёт Bothost. Не публикуйте строку подключения и не помещайте её в Git.

Таблицы создаются автоматически при запуске. Если DATABASE_URL отсутствует,
приложение использует прежнюю SQLite: это режим совместимости, а не PostgreSQL.
После запуска обязательно проверьте поле `database` в `/health`.

Если в прежней SQLite есть нужные заказы, до переключения сделайте резервную
копию и перенесите данные отдельно. Эта сборка не выполняет автоматический
перенос заказов из SQLite в PostgreSQL. Не удаляйте старый файл базы.

## 2. Обновите приложение

Сохраните существующие переменные окружения и резервную копию `/app/data`.
Загрузите новые файлы, не заменяя постоянную папку data, и выполните полную
пересборку: добавлены psycopg и пул подключений. Главный файл — `main.py`,
порт — `8000`, запуск — `python main.py`. Dockerfile также включён.

Нужен один экземпляр приложения / один Uvicorn worker. PostgreSQL-блокировка
не даст двум экземплярам одновременно обрабатывать оплаченные заказы.
Если при обновлении новый контейнер пишет «Самовывоз уже запущен», остановите
старый экземпляр и запустите новый. Не включайте горизонтальное масштабирование.

## 3. Переменные окружения

Пока подключается ЮKassa, оставьте режим каталога:

```dotenv
APP_MODE=catalog
PUBLIC_URL=https://ВАШ-ДОМЕН.bothost.tech
DATABASE_URL=СТРОКА_ПОДКЛЮЧЕНИЯ_ИЗ_BOTHOST
PHOTO_DIR=/app/data/photos
CATALOG_SYNC_SECONDS=300
CATALOG_MAX_AGE_SECONDS=900
PHOTO_REFRESH_SECONDS=86400
PHOTO_CACHE_MAX_MB=1024
```

Оставьте уже работающие SABY_CLIENT_ID, SABY_APP_SECRET, SABY_SECRET_KEY,
SABY_STORE_PRICES, BOT_TOKEN и BOT_USERNAME. SABY_STORE_PRICES должен быть
непустым JSON вида `{"123":456}`, без внешних одинарных кавычек в панели.
PUBLIC_URL укажите настоящий, без завершающего `/`.

Ключи и DATABASE_URL не присылайте в чат. Папка data должна находиться на
постоянном диске Bothost; не переносите фото в static или Git.

## 4. Что произойдёт при старте

1. Проверится база и создадутся таблицы.
2. Откроется приложение; первая выгрузка Saby начнётся в фоне.
3. Пока нет магазина и каталога, витрина покажет ожидание и повторит загрузку.
4. После полной выгрузки всех точек каталог атомарно сохранится в базе.
5. Фотографии начнут скачиваться с ограничением три одновременных загрузки.
   До завершения могут быть заглушки; открытая витрина повторит загрузку фото.

Открытие каталога и фотографий больше не вызывает запросов к Saby.
Очередная синхронизация запускается через 300 секунд после завершения предыдущей.
Фото проверяются повторно не чаще раза в сутки; изменившиеся ссылки Saby
скачиваются при следующей синхронизации. Ошибка одной фотографии не отменяет
каталог. Сбой выгрузки оставляет предыдущий полный каталог.

Прайсы при оформлении берутся только с сервера. Если последняя полная выгрузка
старше 900 секунд, создание нового заказа временно блокируется. Это ограничивает
возраст данных, но не гарантирует наличие: товар может быть продан между
синхронизацией и оформлением. Календарь самовывоза и передача заказа по-прежнему
обращаются к Saby по необходимости.

При смене прайса старые цены точки не используются до новой выгрузки.
После перезапуска сохранённый каталог доступен без ожидания ответа Saby.

## 5. Проверка

Откройте `https://ВАШ-ДОМЕН.bothost.tech/health`:

```json
{"ok":true,"mode":"catalog","database":"postgresql","catalog_ready":true}
```

В терминале работающего приложения:

```sh
python manage.py storage-check
python manage.py catalog-status
```

Первая команда проверяет подключение и запись в папку фото. Вторая показывает
результат синхронизации и число ошибок фото. `ok: true` означает, что каталог
сохранён, даже если `photos_failed` больше нуля. Для отдельной диагностики Saby:

```sh
python manage.py saby-photos --name "часть названия"
```

Перезапустите приложение и убедитесь, что витрина и фото сохранились.
Затем проверьте обновление цены в Saby: новая цена должна появиться после
очередной синхронизации и повторного открытия витрины.

`python manage.py catalog-sync` предназначен для отдельного запуска без
работающего веб-процесса (one-off контейнер с тем же окружением). В обычном
терминале работающего приложения его заменяет автоматическая синхронизация.

## 6. Диск и резервные копии

Лимит локальных фото по умолчанию — 1024 МБ. При достижении лимита сохраняются
уже скачанные файлы; новые загрузки учитываются как ошибки. Увеличивайте
PHOTO_CACHE_MAX_MB только после проверки свободного места. Фото, исчезнувшие
из текущих прайсов и не обновлявшиеся больше 7 дней, удаляются автоматически.

Нужно подтвердить в Bothost, что их бэкапы покрывают и PostgreSQL, и /app/data.
Не считайте постоянное хранилище резервной копией. Фото товаров можно повторно
получить из Saby, пока они там доступны; заказы нужно резервировать отдельно.

## 7. Подключение заказов и оплаты

В этой поставке сохранены прежние адаптеры Saby, ЮKassa и Telegram.
Для проверки без списаний используйте APP_MODE=integration с тестовым ключом
ЮKassa. Пока ключей нет, APP_MODE=catalog — полноценная витрина без оформления.
Перечень переменных и приёмка интеграции приведены в README.md.

Для ответов продавцов укажите оба справочника:

```dotenv
SABY_STORE_CHATS={"123":"-1001234567890"}
SABY_STORE_STAFF={"123":[111111111,222222222]}
```

Сотрудник должен отвечать на сообщение бота о нужном заказе в разрешённом чате.
Список Telegram ID работников задаётся явно. Реальные платежи по умолчанию
отключены и включаются только после проверки всей цепочки и электронных чеков.

В подготовке сборки доступ к вашему кабинету Bothost и реальные ключи не
использовались. Загрузка архива и заполнение переменных выполняются в панели.
